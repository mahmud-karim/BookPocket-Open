# Shared contract v1

JSON keys use snake_case. IDs are opaque strings. Times are ISO8601 UTC unless an audio duration/offset in seconds. Never identify source content by display page. Errors use HTTP statuses and `{ "detail": "actionable explanation" }`. All /v1 endpoints require a device bearer token except health and the explicitly described pairing endpoints. Local studio administrative access is separate, loopback-only, with same-origin protection and a launcher-provided session credential.

## Data
- Book: `{id,title,author,language,source_sha256,chapters,created_at}`. Chapters: `{id,title,href,segments}`. Segment: `{id,text,kind,locator}`; kind paragraph/heading; locator is a Readium-compatible JSON object with href, type, optional title, locations, text. Segment IDs are SHA256 of source_sha256 + href + ordinal + original normalized text (UTF-8, newline-separated). Preserve immutable originals and import format version. Clients may create/import the same normalized manifest.
- Voice: `{id,name,engine,kind,language,created_at}`; kind preset/clone/designed. No reference file paths in public API. Engines: `{id,name,available,supports_cloning,languages,license,reason}`. Available means usable installed configuration, never just a known engine name.
- Generation request: `{request_id,book_id,segment_ids,engine,voice_id,language,pronunciation_rules,announce_chapters}`. request_id is a client UUID; repeated identical request returns existing job, conflicting payload gives 409. pronunciation_rules: array of `{term,replacement,enabled}`. Optional `cast` maps segment ID to voice ID without changing other semantics. Optional UUID `take_id` requests fresh audio rather than reusing previous takes; retries retain both request_id and take_id. Sampling engines may vary across takes; deterministic engines may produce identical audio.
- Optional `narration_mode:"single"|"full_cast"` identifies the requested narrator arrangement on requests, jobs and audio assets, and participates in cache identity. Omitted mode on legacy requests is inferred as full cast when a cast or narration plan is present, otherwise single. An explicit full-cast request can contain narrator-only text with an empty plan; it remains a full-cast take. Clients match book, source location and narrator arrangement before enabling playback.
- Optional `source_ranges:[{segment_id,start_offset,end_offset}]` limits generation to exact portions of the original segments. Offsets are Unicode scalar indices, end exclusive. A nonempty list must contain exactly one bounded, nonempty range for each selected segment, without duplicates or additional segments. Missing or empty ranges preserve whole-segment generation. Ranged requests cannot use whole-segment `cast` or chapter announcements. With `source_ranges_cast` capability, they may include a `narration_plan` whose spans are clipped entirely within each selected range; narrator-filled gaps stop at the range boundaries. Synthesis, cache identity, durable retries and portable projects preserve these ranges; audio timings remain offsets into the original unsliced segment. Partial assets report `source_start` and `source_end`. A rendered page is a snapshot of these source ranges, never a stored screen-page identity.
- Job: `{id,book_id,status,engine,voice_id,segment_ids,completed_segments,total_segments,created_at,started_at,finished_at,generation_seconds,error,assets}`. Status queued/running/paused/completed/failed/cancelled. Assets: `{id,segment_id,media_type,duration,sha256,bytes,url,timings}`. timings: `{start,end,start_offset,end_offset}` offsets into original segment text, Unicode scalar offsets; native clients convert explicitly. Job completed only when every required segment has a validated artifact.
- Position: `{book_id,locator,asset_id,audio_seconds,updated_at}`. Library metadata and positions are local first; companion upload explicit.
- Job `voice_name` is optional narrator provenance captured from the actual voice inventory when submitted. Legacy jobs may be backfilled only when that voice ID is observed in inventory. Clients retain it with downloaded takes for offline Kyon matching; a missing name must not be guessed from an opaque voice ID. Jobs also expose their saved `cast` and `narration_plan` metadata.

## Device API routes
- GET /v1/health -> `{api_version:"1",name,version,capabilities?:["source_ranges","source_ranges_cast","analysis_request_id"]}` (public, no private inventory). Clients must verify `source_ranges` capability before submitting a ranged request and `source_ranges_cast` before combining ranges with full-cast narration; older companions may ignore unfamiliar fields. Missing capability requires a companion update, never expanded narration. Clients relying on recoverable analysis submission must first verify `analysis_request_id`; older companions may ignore request IDs and must not be retried as if they deduplicate analysis.
- GET /v1/engines -> `{engines:[]}`; GET /v1/voices -> `{voices:[]}`.
- POST /v1/voices multipart: name,engine,language,reference,optional transcript -> Voice. Engines can report `requires_reference` and `requires_transcript`; managed OmniVoice requires the exact reference transcript and does not download an ASR model. GET /v1/voices/{id}; DELETE /v1/voices/{id}.
- GET /v1/books -> `{books:[]}`; POST /v1/books multipart file (EPUB/TXT), optional manifest (serialized Book without created_at) -> Book. GET /v1/books/{id}; GET /v1/books/{id}/source -> original file. Book ingestion bounded and archive-safe. DELETE /v1/books/{id} only explicit user action.
- POST /v1/jobs -> Job (202); GET /v1/jobs -> `{jobs:[]}`; GET /v1/jobs/{id} -> Job.
- POST /v1/jobs/{id}/cancel, /retry, /pause, /resume -> Job. Completed immutable artifacts can be reused; in-flight generation may finish but must not publish into cancelled job.
- GET /v1/assets/{id} -> audio bytes with range and checksum support. Assets require authorization; URL is API-relative, never an embedded token.
- POST /v1/jobs/{id}/export `{format:"m4b"|"mp3"|"project",include_voice_references?:false}` -> export asset metadata. Voice references and transcripts are excluded by default. Inclusion requires explicit selection.
- POST /v1/projects/import multipart file -> `{book,job,cast,unresolved_voices}` for a portable project. Original source and audio hashes are validated; repeat import is idempotent. Missing clone references remain unresolved. Companion transfer is bounded at 16 GiB compressed and 32 GiB expanded, with 100,000 entries, 100 MiB original source, 20 MiB voice reference and 512 MiB per audio segment. Import streams from its spool, checks available disk space and allows one import at a time; no entire archive is loaded into memory. Legacy expansion remains bounded at 1 GiB. Native offline archive import has its own explicit 20 GiB expanded limit.
- A legacy archive on the same import route returns `{kind:"legacy",books,recordings,voices,pronunciation_rules,positions}`. See companion/README.md for its archive format. GET /v1/legacy-recordings optionally filters by book_id; GET /v1/pronunciations returns saved corrections. Legacy recordings report `mapping:"text_match_without_timings"|"unmapped"` and never claim synchronized timing. Old display-page positions remain separate, unmapped metadata.

## Pairing
- Local studio POST /v1/admin/pairing-tickets -> `{id,code,expires_at}`. Code random >=8 characters, hashed at rest, expires in 10 minutes.
- Phone POST /v1/pairings `{code,device_name}` -> `{id,poll_token,status:"pending"}`; rate-limited, code consumed for a single pending request.
- Local studio GET /v1/admin/pairings -> pending devices; POST /v1/admin/pairings/{id}/approve or /reject.
- Phone GET /v1/pairings/{id} with Authorization: Bearer poll_token -> pending/rejected/expired or `{status:"approved",device_token,device_id}`. Make successful exchange retryable for bounded expiry to survive dropped response.
- Local studio GET /v1/admin/devices; DELETE /v1/admin/devices/{id} revokes. Phone DELETE /v1/devices/current revokes self. Store only hashes of long-lived tokens; Keychain on iOS.
- Local HTTPS identity is verified from QR certificate SHA256 before token exchange; never global trust bypass. User-configured remote HTTPS must pass normal OS validation. HTTP restricted to loopback development only.
- A public HTTPS reverse proxy may use an API path prefix. Clients append API-relative `/v1/...` routes beneath that prefix and constrain redirects to the same HTTPS origin and prefix. When explicitly configured for system certificate validation, the pairing response and QR omit `certificate_sha256`; clients use normal operating-system trust. LAN pairing continues to supply the local certificate pin.
- The optional phone gateway binds only to loopback for a local TLS-terminating proxy. It shares the existing companion state and worker, admits canonical device API routes only, and treats downstream requests as non-local so desktop admin credentials cannot grant device API access. Studio, administrative routes, schema/docs and browser-origin requests are excluded.

## Compatibility

### Word highlighting, pronunciation settings and recording removal

- Capability `word_alignment` enables `POST /v1/jobs/{id}/align` for an existing completed take. It queues durable acoustic alignment and returns the Job with HTTP 202. Jobs add optional `alignment_status` (`queued`, `running`, `completed`, `failed`) and `alignment_error`; clients poll the ordinary authenticated job route. Asset `alignment` is `word` only for validated acoustic/model word timings, otherwise `sentence` or unavailable. Alignment updates timing metadata while retaining the original audio bytes, IDs and hashes. It maps the recording's immutable pronunciation rules back to original Unicode scalar spans. Optional asset `source_timings` retains exact recorded sentence/part boundaries for page trimming, separate from word-highlight `timings`; repair preserves existing boundary evidence. A client must never simulate word timing by evenly dividing a passage.
- Capability `delete_recordings` enables authenticated `DELETE /v1/jobs/{id}` (HTTP 204) for a whole generated take. Clients confirm the take identity before deleting. Removal prevents late worker publication and retains assets still referenced by other takes. Local download removal is a separate offline action; it does not delete the PC's recording or the source book. Failed PC deletion retains the phone's verified download.
  The same route removes failed/cancelled queue entries, including jobs with zero assets or partial progress. Other jobs and their shared assets remain. Durable request tombstones prevent a deleted terminal job from returning through an old retry.
- Capability `pronunciation_settings` enables `PUT /v1/pronunciations` with `{pronunciation_rules,expected_revision}`. GET and successful PUT return `{pronunciation_rules,revision}`; legacy revision defaults to zero. Saving validates the complete list and atomically checks its revision; a stale revision returns 409 without overwriting corrections. Phone drafts are durable and must not be overwritten by inventory refresh. Rules affect newly generated audio, never displayed publication text or existing recordings. On-device draft previews are labelled explicitly and do not claim the PC narrator's pronunciation.

An optional Pocket Hub-owned start receiver can serve the same phone API mount while the companion is stopped. `POST /v1/companion/start` accepts exactly `{request_id:UUID}` using the existing device bearer credential. It checks the current device pairing store before dispatching only the fixed `start bookopen` manager command; revoked or unknown devices are rejected even while the companion is offline. Retries with the same device/request ID reuse an acknowledged launch for five minutes; starts are limited to eight per device per minute. The response `{status:"starting"}` is an acknowledgement, not authenticated companion readiness. Clients must subsequently verify health and device access before showing Connected. An installation without this optional receiver returns 404. `GET /v1/companion/receiver-health` describes only receiver readiness and must never establish companion connectivity. Ordinary phone uploads, downloads and ranges remain streamed through the receiver to the existing protected gateway; desktop admin routes stay excluded.

## Additions: studio setup and casting
- The local studio is served on loopback HTTP 8782; the phone endpoint uses pinned HTTPS 8783. GET /v1/admin/connection returns `{url,certificate_sha256}`. QR payload is `{url,certificate_sha256,code}`. A development listener uses HTTP only on loopback.
- POST /v1/admin/engines/{kokoro|qwen3|omnivoice}/install queues model installation. GET /v1/admin/engines/installations returns `{installations:[{engine,status,error,created_at,started_at,finished_at?}]}`; queued installations have a null started_at. Actual synthesis/model validation precedes availability. Rendering, speaker analysis and model installation share one heavy-work lease. Pausing or cancelling a job does not free that lease while its in-flight model call is still finishing; waiting work stays queued until the lease is released.
- GET/PUT /v1/admin/analyzer uses `{url,model,api_key?,max_output_tokens?:4096}`. The output budget is an integer from 256 through 16384. GET never returns the key, only `configured,url,model,has_api_key,hosted,max_output_tokens`. Changing origin must not forward an existing key. Hosted analysis requires explicit per-request `allow_hosted:true`.
- GET/PUT /v1/books/{id}/cast uses `{characters:[{id,name,aliases,voice_id}],assignments:[{id,segment_id,start_offset,end_offset,character_id,confidence,reviewed}]}`. Offsets are Unicode scalar indices, end exclusive, ordered and nonoverlapping within a segment. Analysis suggestions are unreviewed. User-reviewed assignments survive reanalysis.
  Analysis also preserves saved edits and deletions made after its starting snapshot, including exact alias removal and changed unreviewed assignments. Deleted and moved assignments protect their old source ranges even if the model generates different IDs. Clearing a previously populated cast stays empty; a cast that was already empty can receive first-time suggestions. Clients retain unsaved drafts in memory and merge arrivals against the starting snapshot; this does not persist unsaved edits across application termination.
- POST /v1/books/{id}/analyze `{allow_hosted:false,request_id?:UUID}` returns an asynchronous persisted analysis `{id,book_id,status,completed_segments,total_segments,created_at,error,finished_at?,warnings?:[]}`; GET /v1/analyses/{id} polls it. An identical request ID, book ID and captured hosted-consent value returns the same persisted job without another model request, including after completion, failure, restart or analyzer configuration changes. Conflicting reuse returns 409. Request identity is recorded atomically with the queued job before returning; omitted IDs retain legacy fresh-request behavior. Known retries do not require the current analyzer configuration. An explicitly new analysis uses a new UUID. Clients retain the original starting cast, consent and UUID through a lost confirmation, block saves until that submission is resolved, and merge later results against that starting cast; the unsaved draft is still memory-only. Clients display warnings alongside suggestions. Automatic extraction currently covers paired double-quoted dialogue; unsupported or ambiguous conventions require manual casting. Suggestions remain unreviewed.
- Analyzer model output may use verbatim `source_text` anchors with an optional occurrence index. The server derives Unicode scalar offsets and rejects missing or ambiguous anchors; model output cannot replace source text. Suggestions still require review.
- Capability `chapter_analysis` adds optional `chapter_ids:[string]` and `force_reanalyze:false` to analysis requests. Selected IDs must be unique chapters of this original book. Omitting `chapter_ids` retains legacy fresh whole-book analysis; explicitly supplying all chapter IDs permits coverage reuse. Scope, hosted consent and force participate in request identity. Completed/in-flight compatible chapter work is reused unless force is explicit; mixed selections analyze missing chapters and report additive `chapter_ids` and `reused_chapter_ids` on the analysis result. Coverage is tied to original source and analysis configuration/prompt version. `GET /v1/books/{id}/analysis-status` returns `{chapters:[{chapter_id,status,analysis_id?,error?}]}`, where status is not_analyzed/queued/running/completed/failed. Completion means analysis finished, not that its suggestions are reviewed or voices exist. A supported chapter with no quoted dialogue may complete without a model call. Scoped merges retain all assignments outside the analyzed chapters and preserve reviewed assignments, saved voice choices and in-flight edits/deletions. Cache reuse reads the current saved cast; it never replays deleted stale suggestions.
- Capability `voice_previews` enables authenticated `POST /v1/voice-previews` with `{request_id:UUID,voice_id,text,language}` (text 1–1000 characters), `GET /v1/voice-previews/{id}`, and `DELETE /v1/voice-previews/{id}` (204). The durable result is `{id,voice_id,status,created_at,error?,asset?}` with optional captured engine/voice_name/text provenance; status queued/running/completed/failed/cancelled. A completed asset is actual validated synthesis from the selected voice, downloadable through the ordinary protected asset route. It never substitutes reference playback or Apple speech. Auditions use the shared heavy-work lease and stay separate from book production jobs. Retry identity preserves captured voice/reference settings; conflicting request reuse gives 409 and a deleted preview's delayed recreation gives 410. Deletion cancels publication and removes only unshared preview media. Active previews retain their voice reference. No public source upload contains private audition audio or voice samples.
- Generation supports `narration_plan:[{segment_id,start_offset,end_offset,voice_id}]`. Each original source segment produces one joined asset containing every selected voice span and narrator-filled gaps. The ordered plan and voice revisions participate in the cache key. `cast` remains a whole-segment compatibility field.
- Asset `alignment` reports `word` or `sentence`; do not infer word precision from a sentence interval. Scalar offsets always refer to original display text, even when pronunciation substitutions affect synthesis.
- Book `cover_url` is an optional protected API-relative location. GET /v1/books/{id}/cover returns a validated cover image.
- Voice upload accepts optional `trim_start` and `trim_end` seconds. GET /v1/voices/{id}/reference returns a protected local clone reference. External voice adapters need not expose a reference.

API v1 is owned by root. Additive optional fields are allowed; communicate any route/type change to root and the other client implementers. Companion Pydantic models generate OpenAPI. Shared fixtures verify JSON parsing, span offsets including emoji, restart idempotency and errors across clients.
